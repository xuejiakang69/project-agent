# 前端修改流程

## 核心流程

只读分析 → 确认需求 → 修改方案 → 用户确认 → 修改 → 验证 → 汇报

## 第一阶段：只读分析

根据任务检查：

- `vue-project/src/views/`
- `vue-project/src/components/`
- `vue-project/src/api/`
- `vue-project/src/router/`
- `vue-project/src/stores/`
- 相关配置文件。

确认现有代码结构和实现方式。

不要修改文件。

## 第二阶段：确认需求

如果无法从项目和用户描述确定：

- 页面交互；
- 接口路径；
- 请求方式；
- 请求参数；
- 响应结构；
- 错误处理；
- 加载状态；
- 权限要求；

则先询问用户。

不要自行猜测。

## 第三阶段：修改方案

使用：

# 修改方案

1. 修改目标：
2. 当前问题：
3. 涉及文件：
4. 修改内容：
5. 接口变化：
6. 页面交互：
7. 影响范围：
8. 验证方式：

等待用户确认。

## 第四阶段：确认后修改

只有用户明确确认后才能：

- 修改 Vue 文件；
- 修改 API；
- 修改路由；
- 修改状态管理；
- 修改配置；
- 新增组件。

不得擅自扩大修改范围。
